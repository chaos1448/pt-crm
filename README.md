# PT 고객관리 (Google Calendar 연동)

회원 등록 → 예약 → **출석 체크 시 잔여 회차 자동 차감**.
구글 캘린더와 **양방향 동기화**(앱에서 잡은 예약은 캘린더에 뜨고, 캘린더에서 만든 일정은 앱이 흡수).

파일 4개짜리 정적 웹앱입니다. 서버 필요 없음.

```
index.html     앱 전체 (46KB, 이 파일 하나가 프로그램)
schema.sql     Supabase 테이블(crm_members·crm_packages·crm_bookings) + 보안규칙
manifest.json  홈화면 추가(PWA)용
icon-192.png / icon-512.png
```

## 준비 3단계 (한 번만, 약 15분)

### 1단계 — Supabase (데이터 저장소)

1. https://supabase.com 접속 → 구글로 가입 → **New project**
   - Name: `pt-crm` / Region: **Northeast Asia (Seoul)** / DB 비밀번호는 아무거나 (기억 안 해도 됨)
   - 생성까지 2분 정도 걸립니다.
2. 왼쪽 메뉴 **SQL Editor** → **New query** → `schema.sql` 내용을 통째로 붙여넣고 **RUN**
   - `Success. No rows returned` 나오면 성공.
3. 왼쪽 아래 **Project Settings → API** 에서 두 값을 복사해 둡니다.
   - **Project URL** (`https://xxxx.supabase.co`)
   - **anon public** 키 — 새 대시보드에서는 **Publishable key** 로 표시되며 `sb_publishable_...` 로 시작합니다. 둘 중 보이는 걸 쓰면 됩니다.
   - ⚠️ `service_role` / `secret` 키는 **절대** 쓰지 마세요. 소스가 공개되므로 유출되면 DB가 통째로 열립니다.

### 2단계 — Google Cloud (캘린더 연동)

1. https://console.cloud.google.com → 상단 프로젝트 선택 → **새 프로젝트** (`pt-crm`)
2. **API 및 서비스 → 라이브러리** → `Google Calendar API` 검색 → **사용 설정**
3. **API 및 서비스 → OAuth 동의 화면**
   - User Type: **외부** → 만들기
   - 앱 이름 `PT 고객관리`, 사용자 지원 이메일 / 개발자 이메일 = 본인 메일
   - 범위(Scopes)는 그냥 넘어가도 됩니다
   - **대상(Test users)** 에 **본인 구글 계정을 반드시 추가** ← 빠뜨리면 로그인이 막힙니다
4. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 유형: **웹 애플리케이션**
   - **승인된 자바스크립트 원본** 에 2개 추가
     - `http://localhost:8080`
     - `https://chaos1448.github.io`
   - **승인된 리디렉션 URI** 에 1개 추가
     - `https://fropdvyqchmmtcbtzprk.supabase.co/auth/v1/callback`
   - 만들면 **클라이언트 ID** 와 **클라이언트 보안 비밀번호** 가 나옵니다. 둘 다 복사.
5. 다시 Supabase → **Authentication → Sign In / Providers → Google**
   - 켜고, 위에서 복사한 **클라이언트 ID / 보안 비밀번호** 붙여넣고 저장
   - 같은 화면의 **Callback URL** 이 4번에서 넣은 리디렉션 URI와 같은지 확인

### 3단계 — GitHub Pages (배포)

1. GitHub(`chaos1448`)에서 새 저장소 생성 — 이름 `pt-crm`, **Public**
2. 이 폴더의 파일 4개 + 아이콘 2개를 업로드 (드래그앤드롭으로 됩니다)
3. 저장소 **Settings → Pages** → Source: `Deploy from a branch` → Branch: `main` / `/ (root)` → Save
4. 1~2분 뒤 `https://chaos1448.github.io/pt-crm/` 로 접속

### 4단계 — 값 3개를 코드에 박아넣기 (남에게 넘겨줄 경우 필수)

`index.html` 을 열면 맨 위 `<script>` 안에 이 블록이 있습니다. 여기에 값을 채워 넣고 다시 업로드하세요.

```js
const PRESET = {
  sb_url : '',   // 1단계에서 복사한 Project URL
  sb_key : '',   // 1단계에서 복사한 anon key
  gcid   : '',   // 2단계에서 만든 OAuth 클라이언트 ID
  cal    : ''    // 비워두면 기본 캘린더
};
```

- **채워 넣으면** → 실제 사용자는 접속해서 **`구글 계정으로 로그인` 버튼 하나만** 누르면 됩니다.
- **비워두면** → 접속할 때마다 설정 화면이 먼저 뜹니다. (혼자 쓸 때만 이래도 됩니다)

### 첫 실행

구글 계정으로 로그인 → 캘린더 권한 허용 → 끝.

마지막으로 **⚙️ 설정 → 캘린더 목록 불러오기** 에서 연동할 캘린더를 고르세요.
(PT 전용 캘린더를 따로 만들어 두면 개인 일정과 안 섞여서 편합니다.)

## 다른 사람에게 만들어 주는 경우

Supabase · Google Cloud · GitHub 계정은 **만드는 사람 것**이면 됩니다.
실제 사용자는 URL을 열고 **본인 구글 계정으로 로그인**만 하면 되고, 예약은 그 사람 구글 캘린더에 뜹니다.

넘기기 전에 반드시 확인할 것:

1. **Google Cloud → OAuth 동의 화면 → 테스트 사용자** 에 **실제 사용자의 구글 계정을 추가**하세요.
   빠뜨리면 그 사람은 `액세스 차단됨` 이 뜨면서 로그인 자체가 안 됩니다.
2. 위 **4단계 PRESET** 을 채워서 배포하세요. 안 그러면 그 사람이 URL·키를 직접 붙여넣어야 합니다.
3. 데이터는 **로그인 계정별로 완전히 분리**됩니다.
   - 만든 사람이 테스트로 넣은 회원은 실제 사용자에게 안 보입니다 (깨끗하게 시작)
   - 반대로 만든 사람도 실제 사용자의 데이터를 볼 수 없습니다. 지원·확인이 필요하면 `schema.sql` 의 RLS 정책을 계정 두 개 허용으로 바꿔야 합니다.

## 사용법

| 하고 싶은 것 | 방법 |
|---|---|
| 회원 등록 | 👥 회원 → **+ 회원 등록** → 저장하면 바로 회차 등록 창이 뜹니다 |
| 회차/결제 등록 | 회원 카드 클릭 → **+ 회차 등록** (30회 / 금액 / 만료일) |
| 예약 잡기 | 📅 예약 → 캘린더 빈칸 클릭 → 회원 선택 → 예약 |
| **잔여 차감** | 수업 후 예약 블록 클릭 → **✅ 출석 완료** → 잔여 1회 차감 |
| 노쇼 처리 | 예약 블록 클릭 → **🚫 노쇼** (기본은 차감 안 함, 설정에서 변경 가능) |
| 폰에서 쓰기 | 배포 URL을 사파리로 열고 **공유 → 홈 화면에 추가** |

### 잔여 회차 계산

```
잔여 = 등록한 회차 합계 − 출석 완료 건수
       (설정에서 '노쇼도 차감' 켜면 노쇼도 포함)
```

예약만 잡아둔 상태에서는 차감되지 않습니다. 당일 취소·노쇼가 잔여를 갉아먹지 않는 방식입니다.

### 양방향 동기화가 도는 방식

- 화면에 **보이는 기간(그 주)** 만 구글 캘린더와 대조합니다. 앱을 열 때, 주를 넘길 때, 3분마다, `↻ 동기화` 누를 때 실행.
- **앱 → 캘린더**: 예약을 만들면 캘린더에 `홍길동 PT` 일정이 생깁니다.
- **캘린더 → 앱**: 캘린더에서 시간을 옮기면 앱 예약 시간도 따라옵니다. 캘린더에서 지우면 앱 예약도 지워집니다.
- 캘린더에서 직접 만든 일정은 **제목에 회원 이름이 들어 있으면 자동으로** 예약으로 잡힙니다.
  이름이 없거나 애매하면 캘린더 위쪽에 **🔗 미연결 일정** 으로 뜨고, 눌러서 회원을 고르면 연결됩니다.
  자동 연결이 부담스러우면 ⚙️ 설정에서 끄고 전부 수동으로 확인할 수 있습니다.

## 알아두실 점

- **회원 데이터 보안**: GitHub Pages는 소스가 공개라 anon key가 노출됩니다. 그래서 Supabase에 RLS(행 수준 보안)를 걸어 **로그인한 본인 계정의 데이터만** 읽고 쓸 수 있게 해 뒀습니다. `schema.sql`을 반드시 그대로 실행하세요. 이 부분을 지우면 URL만 아는 사람이 고객명단을 볼 수 있습니다.
- **OAuth 동의 화면 '테스트' 상태**: 테스트 사용자로 등록한 계정만 로그인됩니다. 혼자 쓰시면 이대로가 낫습니다(구글 심사 불필요). 다만 리프레시 토큰이 7일마다 만료되므로, 가끔 구글 권한을 다시 승인해야 할 수 있습니다 (⚙️ 설정 → *구글 캘린더 권한 다시 요청*).
- **삭제는 되돌릴 수 없습니다**: 회원을 삭제하면 그 회원의 예약·결제 기록이 함께 사라집니다.
- **로컬 테스트**: 이 폴더에서 `python3 -m http.server 8080` 실행 후 `http://localhost:8080` 접속.
